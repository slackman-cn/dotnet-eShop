# WeKnora 0.9.0 功能说明

本文说明 Tencent WeKnora 在提交 `81a03046bed16504d249bb22591492966fc9c9b9`（仓库 `VERSION` 为 `0.9.0`）中实际具备的产品能力。路径均相对于该源码树。系统架构、进程拓扑和设计权衡见同目录 `architecture.md`。本文按能力与使用场景组织，而不是按源码目录罗列文件。判断一项能力是默认核心还是选配时，依据是：不打开对应 profile、不配置对应模型或开关时，最小的五个 Compose 服务能否完成该能力；若不能，则列为选配，并写明依赖。文中不记录任何密钥明文，也不把未启动的运行系统上的效果写成已验证结论。

用户认为 WeKnora 功能面很宽，许多能力是选配，部分机制存在重叠，因而适合企业里不同部门、不同资料形态和不同集成需求。下面用具体入口、开关和依赖把这一判断落到 0.9.0 的实现上。若代码与“看起来可选”不完全一致，会直接写出文件证据，而不补充源码中不存在的企业功能。

## 一、如何区分默认核心与选配

默认核心可以概括为：在一个工作空间里创建文档型知识库，上传文件、URL 或手工文本，由 `docreader` 解析、`app` 分块并在 ParadeDB 中建立向量与关键词索引，然后在 Web 会话里做带引用的检索增强问答。为此至少需要配置对话模型（`KnowledgeQA`）和嵌入模型（`Embedding`），并完成用户注册或 Lite 下的自动开户。向量与关键词两条索引管线在 `DefaultIndexingStrategy()` 中默认打开，Wiki 与图谱默认关闭。Web 前端、会话管理、成员角色、API Key、分块编辑、预览下载、系统信息，都属于这条最小路径上的配套能力。

选配则覆盖：重排、视觉、语音；知识图谱（Neo4j）；独立向量库；对象存储（某些图片多模态路径还会变成前置条件）；Wiki 自动生成；FAQ 库类型；数据源同步；联网搜索；IM 与嵌入渠道；MCP 客户端与对外端点；Agent 技能与沙箱；长期记忆；自动化与内置助手；OIDC；Langfuse；评测；以及多种客户端形态。选配不是“安装了但没有菜单”，而是代码常驻、默认关闭或需额外进程与模型。企业落地时通常先打通核心问答，再按场景打开其中几项，而不是一次启用 Compose 的 `full` profile。

还有一类应当称为“发行收缩”而不是选配：Lite 与桌面构建会关闭组织、远程沙箱等能力，并把存储和队列换成 SQLite 与进程内执行器。它们不是标准 Compose 部署里可以打开的开关，而是另一种发行边界。

## 三、空间、认证与权限

工作空间（租户）是资源隔离的基本单位，用户是登录账号，二者通过 `tenant_members` 关联。界面入口是登录、注册、邀请加入、工作空间引导，以及设置中的租户信息与成员页。API 入口集中在 `internal/router/routes_auth_tenant.go`：`POST /auth/register`、`/auth/register-by-invite`、`/auth/login`、`/auth/logout`、`/auth/refresh`、`/auth/validate`、`/auth/change-password`、`/auth/me/preferences`、`/auth/switch-tenant`，以及 OIDC 的配置、URL、回调与启动接口。当前空间的成员、邀请、API Key、审计、离开空间也在租户分组下。

角色有四级，定义于 `internal/types/tenant_member.go`：Owner、Admin、Contributor、Viewer。Owner 可删除空间或变更 Owner；Admin 管理成员、集成和多数空间级设置，但不能做 Owner 专属操作；Contributor 可创建知识库和智能体并编辑内容；Viewer 只读并可以问答。设置导航的最低可见角色写在 `frontend/src/config/settingsAccess.ts`：一般设置、模型、系统信息、用户资料等 Viewer 可见，Ollama、联网搜索、向量存储、解析、对象存储、沙箱、技能、MCP、聊天历史等需 Admin，成员管理的管理快捷入口更严格。后端守卫仍然权威，关闭 `WEKNORA_TENANT_ENABLE_RBAC` 时守卫只记日志后放行，这是灰度行为，企业生产通常应保持开启。

注册策略可按部署关闭公开注册（`DISABLE_REGISTRATION`），改为仅邀请。邀请可以定向发给已有用户，也可以生成带 token 的链接，带有有效期、接受次数和自动接受开关。复杂密码策略可开可关。OIDC 是选配，需 `OIDC_AUTH_ENABLE=true` 并填写发行者、客户端和端点或发现地址，支持 PKCE；`dex` profile 只提供测试用身份源，不是生产 IdP。JWT 使用访问令牌与刷新令牌，密钥来自 `JWT_SECRET`。

API Key 是程序接入的主方式，在设置或工具箱中创建，接口为租户下的 `/api-keys`。密钥分租户作用域和平台作用域。租户侧能力在前端清单中包括：`retrieve`、`chat`、`read_agents`、`ingest`、`manage_kbs`、`message_history`、`manage_agents`、`manage_mcp_services`、`manage_datasources`、`manage_models`、`manage_vector_stores`、`manage_storage_backends`、`manage_web_search`、`manage_channels`、`run_evaluations`、`manage_members`、`manage_spaces`、`manage_tenant_settings`。默认新建 Key 只带 `retrieve`、`chat`、`read_agents`。其中检索、问答、入库、管理知识库、管理智能体、管理数据源可以再限制到指定知识库 ID。平台 Key 另有读取或管理租户、系统设置、运行时和审计的能力。未在路由策略表登记的接口对 Key 默认拒绝。企业可以把“只允许检索某个库”的集成机器人与“可入库的同步作业”分成两把钥匙，而不必共享管理员账号。

组织用于跨工作空间共享知识库和智能体，界面在 `/organizations` 与 `/platform/organizations`。成员可以搜索空间、邀请、审批加入、设置分享权限。Lite 发行通过部署能力接口声明组织不受支持。对需要集团内多个部门空间协同、又必须保持空间计费和配额独立的企业，组织是标准发行里的选项；单部门部署可以完全不用。

凭证保险库、用户环境变量、个人偏好与浏览器连接属于身份周边能力，分别在设置的对应分节。环境变量有用户级与空间级，技能安装会用到；保险库保存敏感凭据，避免写进普通智能体配置文本。这些对 Viewer 开放“管理自己的那一份”，空间级值仍由 Admin 控制。

典型场景包括：部门私有知识空间、邀请外部协作的 Viewer、用 API Key 把检索接到内部机器人、用 OIDC 接入公司 IdP、用组织把同一套制度库共享给多个业务空间。不需要的注册方式、OIDC 和组织都可以保持关闭。

## 四、知识库与知识对象

知识库是资料和问答范围的容器。界面主入口是 `/knowledgeBase` 列表和 `/knowledge-bases/:kbId` 详情，全局与库内都可以进入创建会话。API 在 `routes_knowledge.go`：创建、更新、部分更新、删除、复制、副本、置顶、画像生成、混合检索、活动流、移动目标等。知识库类型有 `document`、`faq`、`wiki`，缺省为文档型。类型会清理不适用的配置：非 FAQ 库没有 `FAQConfig`，非文档库没有自动标签和画像配置。对外暴露的 `capabilities` 字段综合了索引策略和类型，供智能体编辑器按工具需求过滤可用库，序列化时不会输出存储或 VLM 密钥。

文档型知识库承担最常见的企业资料场景：制度、手册、方案、会议纪要。管理员在库设置中绑定模型、分块、解析规则、索引开关、存储和分享。Contributor 可以上传和管理资料。列表支持排序、按解析状态过滤、文件夹树和标签。文件夹与标签的 API 挂在知识库下，标签还可以批量打到知识对象上。活动与用量在详情或设置中的活动页，接口包含 `GET /knowledge-bases/:id/activity`，便于查看谁在何时导入或检索。AI 生成知识库描述走 `POST /knowledge-bases/:id/profile/generate` 和任务 `kb:profile`，依赖对话模型，属于可选富化，不是创建库的前提。自动标签同样可选，在文档库上把已有标签自动关联到新文档，任务类型为 `knowledge:auto_tag`。

知识对象的创建入口有三条核心路径：`POST /knowledge-bases/:id/knowledge/file`、`/url`、`/manual`。此外还有重解析、取消解析、批量重解析、批量删除、移动、批量下载、预览、下载、更新手工知识、按块更新图片、搜索、阶段与跨度查询。上传后前端通过详情或进度接口跟踪 `pending → processing → finalizing → completed`，失败或取消后可以重解析。文件哈希用于去重，避免同一文件在库内重复占用配额。预览与下载走授权后的文件接口，不把对象存储的长期密钥交给浏览器。

画廊与图片检索是文档库上的增强：库内图片列表、画廊配置、以及把图片作为检索条件的路径，依赖多模态嵌入或 OCR/描述子块。未配置视觉模型时，画廊仍可能展示已抽出的图片，但图片向量检索不会可用。分块编辑允许查看修订并回滚，生成问题可以按块重新生成。复制知识库与移动知识是异步维护任务，有独立进度接口，用于把资料在空间内重组，而不必重新上传。这些操作需要写权限，并走删除与索引维护队列，以免与正在解析的任务冲突。

对企业而言，知识库功能的核心价值是“按权限边界组织资料”。一个空间可以有多个库，分别对应不同保密级别或业务线；分享可以把某个库以只读或更细的权限交给组织内其他空间；置顶和收藏只影响个人导航。不需要 Wiki、图谱或数据源的团队，只使用上传和问答即可，这些开关默认不必打开。

## 五、文档处理与解析

解析发生在 `docreader` 进程，对用户表现为“上传之后开始处理”。支持的格式在解析器目录中可见，包括 PDF、Word、Excel、HTML、网页、EPUB、Markdown、图片、XMind、MHTML 等，官方介绍还把扫描件 OCR、Office 转换和网页抓取列为针对杂乱文档的能力。知识库可以按文件类型配置 `ParserEngineRules`，在默认引擎和 OpenDataLoader 等备选引擎之间切换。`odl-hybrid` profile 提供混合解析后端，只有规则真正指向它时才进入数据路径。MinerU、PaddleOCR、WeKnora Cloud 等路径在超时与配置项中出现，属于可选的外部或云端解析，需要相应地址和超时配置，不是默认 Compose 的一部分。

PDF 相关能力很细，但都是选配调参而不是第二套产品：渲染 DPI、JPEG 质量、扫描件判定或强制扫描件、版式排序、标题检测、隐藏文本过滤、嵌入图片抽取与数量限制、矢量图表区域识别等，均以 `DOCREADER_PDF_*` 环境变量存在。预处理工人数、内存、像素上限影响扫描件和图片路径的资源消耗。对这些参数不熟悉的部署，应保持默认，只在具体文件类型失败时再调。Excel 还有百分比文本化等选项。飞书云文档的旧解析模式变量在 `.env.example` 中标明已废弃，只为兼容短暂版本，新路径应走数据源连接器。

图片处理管线可在 `default` 与 `smartocr` 之间选择，任务提交时冻结本轮配置。OCR 预处理默认关闭，可按库打开。多模态后处理任务 `image:multimodal` 做 OCR 与视觉描述，依赖视觉模型，并可能要求对象存储配置完整。音频文件依赖 ASR 模型，未配置时上传会在入队前被拒绝。会话里的临时附件走更高优先级的 `chat_attachment` 队列，解析后只服务当前会话，不自动进入知识库；TTL 由相关环境变量控制。

解析失败可以重试、取消或重解析；巡检会把长时间没有跨度心跳的卡住任务标为失败。对企业扫描件、合同 PDF、表格年报这类资料，解析质量往往比再换一个向量库更关键。选配的混合解析和云端引擎是为这些难例准备的，而不是每个库的必选项。URL 导入和网页解析还受 SSRF 策略约束，不能把任意内网地址当作“网页知识”抓取。

## 六、分块与索引策略

分块配置在库设置的分块页，结构为 `ChunkingConfig`：`chunk_size` 范围在类型标签中为 100 到 10000，`chunk_overlap`、分隔标记、是否启用父子分块、父块与子块大小、可选 token 上限、语言提示，以及策略 `auto`、`heading`、`heuristic`、`recursive`、`legacy`。`auto` 内部有回退链，官方分块文档把它分成若干层级，失败时退到更保守的切法。父子分块时，子块用于嵌入，父块只作为上下文，类型为 `parent_text` 的块不参与向量索引。单次上传可以覆盖库默认分块，并在重解析时沿用。调试入口包括库设置中的分块调试页，对应后端预览或调试接口，用于在正式入库前观察切分结果。

索引策略四个开关决定分块之后走哪些管线。默认打开向量与关键词，关闭 Wiki 与图谱。只想做关键词检索的库仍会在类型层被要求配置嵌入模型，这是契约上的耦合，配置向导应按此准备，而不能假设“关掉向量就可以不配嵌入”。Wiki 与图谱打开后会增加富化任务和模型消耗。能力字段把这些开关以及是否为 FAQ 库暴露给智能体预设，例如 Wiki 问答预设会过滤没有 Wiki 能力的库，数据分析预设可以对 FAQ 做排除。企业可以按库选择：制度库只用向量加关键词；产品关系库再开图谱；需要可浏览页面时再开 Wiki。不必让所有库共享同一套最重的管线。

重建索引是独立操作，用于在变更嵌入模型或修复索引后批量重做。必须注意 `image_vector` 分块不能按文本重建路径处理，否则图片向量检索会坏掉。删除、移动、克隆都会维护索引，而不是只改 Postgres 行。


## 七、检索引擎与混合检索

默认检索引擎是 ParadeDB（`RETRIEVE_DRIVER=postgres`），在同一数据库中同时提供向量检索和 BM25 关键词检索，标准部署不必再开独立向量库。Lite 使用 `sqlite` 与 `sqlite-vec`。此外，启动注册函数还支持 Elasticsearch v7/v8、OpenSearch、Qdrant、Milvus、Weaviate、Doris 和腾讯云 VectorDB。这些引擎通过环境变量或设置页中的向量存储配置接入，界面入口是设置的“向量存储”以及库设置中的向量存储绑定。API 在 `/vector-stores` 分组：类型列表、测试连接、增删改、设为默认。Admin 才能管理，API Key 需要 `manage_vector_stores`。

一次查询是否走多个引擎，取决于知识库或租户绑定的存储组，而不是把所有已注册引擎自动广播。混合检索对用户暴露为知识库的 `hybrid-search` 接口，以及问答管线内部的分块检索。结果可以再经过重排、FAQ 加权、MMR、Wiki 加权等融合步骤。独立的 hybrid-search 不调用对话模型，适合调试召回、给外部系统只要证据列表、或供智能体工具使用。类型常量里的 Infinity 和 ElasticFaiss 没有可部署实例，不应在设置里当作可选项来规划采购。

企业选用独立向量库通常是因为已有 ES/OpenSearch 运维体系、需要对大规模向量做单独扩容，或必须把检索数据放在指定的云向量库。代价是多一个故障域，并且要处理好 SSRF 白名单、凭证和索引重建。若没有这些约束，保持 ParadeDB 是与默认架构一致的选择。关键词阈值、向量阈值、Top-K 在 `config.yaml` 和可覆盖的会话或租户配置中调整，属于效果调参，不是功能开关。

## 八、问答与会话体验

问答是产品的主交互。界面上，用户从全局或某个知识库进入 `creatChat`，再在 `/chat/:chatid` 中查看流式回答、引用、建议问题和附件。API 主入口是 `POST /api/v1/knowledge-chat/:session_id` 与 `POST /api/v1/agent-chat/:session_id`，另有续流、停止、会话增删改、标题生成、附件上传与预览、fork、rewind、steer、置顶、建议问题、产物下载、消息搜索与批量删除、语音转写。会话列表和历史统计也在聊天路由下。

知识问答路径会加载有限轮次的历史、召回长期记忆（若开启）、改写与意图识别，然后按需并行检索，再重排、抓取网页全文、融合截断，必要时做表格分析，最后流式生成并先推送引用。若没有知识范围且未开联网搜索，则走纯聊天，只保留历史、记忆和生成。标签提及会被解析为检索目标，避免表面上没选库却被降级成闲聊。建议问题可以按消息生成，并有事件接口。会话标题可自动生成。这些体验功能大多依赖对话模型，但不是另一些基础设施进程。

聊天历史保留与清理由设置中的“聊天历史”分节管理，Admin 可配，接口包含历史统计与按会话清空。附件在会话内解析，不默认入库，避免把一次性文件写进长期知识库。制品（artifacts）是智能体或工具产生的文件，可在会话或制品库页下载或删除。Fork 与 rewind 用于从某一轮分出新会话或回到之前的上下文，适合试验不同问法。Steer 允许在生成过程中插入纠正。停止与续流保证用户对长回答有控制权，并在多实例部署下依赖 Redis 流管理。

对企业场景，知识问答适合“对着制度或手册提问并要引用”；纯聊天适合未选库的草稿讨论；需要工具和多步推理时改走智能体入口。同一套会话模型服务这三种方式，但 SSE 事件和权限检查并不完全相同。Viewer 可以提问，但不能改库配置；嵌入和 IM 中的访客只能在渠道绑定的范围内提问。

## 九、模型目录与五类模型

模型管理是把外部或本地推理服务登记为可绑定实例的功能。界面在设置的“模型”分节，系统管理员还有“模型目录”。API 在 `/models`：提供方与目录解析、CRUD、复制、调试、凭证单独读写。类型只有五类。

对话模型（`KnowledgeQA`）用于知识问答、智能体推理，以及摘要、问题生成、图谱抽取、Wiki 合成、自动标签、查询理解、追问建议等所有大模型文本任务。它们通过不同的用途绑定指向可能不同的实例，从而可以让“抽取用一个较便宜的模型、回答用一个较强的模型”，也可以全部指向同一实例。嵌入模型（`Embedding`）用于文档和查询向量化，是默认入库和检索的前提。重排模型（`Rerank`）可选，对召回片段再打分，不支持作为 Ollama 本地源接入。视觉模型（`VLLM`）用于文档或对话中的图片理解。语音模型（`ASR`）用于音频转写，包括知识入库和会话转写接口。

提供方可为本地 Ollama、远程通用接口，以及 `internal/models/providers/` 中声明的多家厂商，协议实现覆盖 OpenAI 兼容、Anthropic Messages、Gemini、DashScope、重排专用接口等。官方文档给出二十余家内置厂商的量级，具体某一家支持哪几类模型要以目录和提供方声明为准。模型目录由系统管理员更新，不会自动创建实例，`deprecated` 只隐藏候选，不改写已有实例的显式参数。内置模型示例 YAML 和环境变量中的 `LLM_*`、`EMBEDDING_*`、`RERANK_*` 用于部署期预置。Ollama 有独立设置页和下载任务，`OLLAMA_OPTIONAL` 控制探测失败是否阻断启动。凭证用 `SYSTEM_AES_KEY` 加密，普通列表和知识库 JSON 不应泄露密钥。

调试接口可以对模型做连通或相似性检查，供排障，不是日常问答入口。复制模型便于在空间内衍生一套不同参数的实例。企业典型用法是：开发环境用 Ollama，生产用公司统一的 OpenAI 兼容网关或云厂商；为嵌入和对话选择不同供应商；重排、视觉、语音按需再加。不需要把目录里出现的所有厂商都配置一遍。

## 十、知识图谱功能

知识图谱在功能上做两件事：入库时从分块抽取实体和关系，问答时沿关系补充相关分块；另外提供不调用模型的只读图查询，供调试或给需要看关系的界面使用。它默认关闭。要启用，必须启动 `neo4j` profile（或外部 Neo4j 加 APOC），设置 `NEO4J_ENABLE=true`，并在知识库打开 `GraphEnabled` 与有效的 `ExtractConfig`。旧变量 `ENABLE_GRAPH_RAG` 已被主应用忽略。系统信息在未启用时报告 `Not Enabled`。初始化向导在未满足部署开关时会拒绝图谱配置。

抽取按分块入队，使用对话模型，而不是单独的图谱模型类型。这会增加入库时延和模型费用。写入 Neo4j 时按知识库和知识 ID 隔离标签。若进程没有驱动，写入会被仓储空操作吞掉，因此只在库开关上打开、却未部署 Neo4j，可能白耗抽取调用。问答中的实体检索与分块检索并行，失败或未抽出实体时不影响向量和关键词命中。独立接口 `POST /api/v1/knowledge-bases/:id/graph-search` 需要读权限和检索类 API Key 能力，查询体有大小限制，结果有种子数和行数上限，并会核对来源分块是否仍有效。未启用或服务不可用时，服务层按声明返回相应错误，而不会在这条只读接口上静默装成“没有实体”。

适合人物、组织、产品、条款之间关系密集的资料，例如客户关系说明、制度里的职责引用、产品组成。纯叙述性手册开图谱的收益通常较小，却会拖慢入库。Wiki 的页面链接不是 Neo4j 图谱，不要把两个开关当成同一个功能。

## 十一、Wiki

Wiki 把知识库变成可浏览、可修订、可互相链接的页面集合，也可以把页面投影为 `wiki_page` 分块，进入普通检索。默认 `WikiEnabled` 为关。打开后，界面在知识库详情的 Wiki 子页，提供页面读写、移动、修订与回滚、文件夹、索引、图视图、统计、搜索、重建链接、检查与自动修复、问题上报与状态更新。路由在 `routes_knowledge.go` 的 `knowledgebase/:kb_id/wiki` 与 `wiki-search` 分组下。摄入与收尾是异步任务 `wiki:ingest`、`wiki:finalize`，由独立 Wiki worker 池执行，收尾带防抖，避免频繁重建。

自动生成与手动编辑是分开的：`IsWikiAutoGenerateEnabled` 要求策略打开且 Wiki 配置允许自动生成。关闭自动生成后，仍可手工编辑已有页面。修订记录编辑来源是管线、智能体、用户还是回滚，并有版本保留上限。内置智能体里有“维基问答”和“维基修订”，类型预设里有 `wiki-qa`，它们依赖库的 Wiki 能力。对企业，Wiki 适合需要“可读的知识门户”而不仅是问答的团队，例如把多份制度重整成条目，并允许指定人员修订。它与文档检索重叠：同一内容可能既在原始分块里，又在 Wiki 页面和页面分块里出现，融合阶段的 Wiki 加权就是用来调节这种重复的。若不需要门户，保持关闭即可避免双份索引和额外模型改写。

## 十二、FAQ

FAQ 是一种知识库类型，也是一种分块类型。官方说明把一条 FAQ 存成一个 Chunk，再通过 API 投影为条目。界面在 FAQ 类型库中管理条目、批量导入、相似问题、字段与标签更新、搜索和导入结果展示。API 包括条目的增删改、批量补丁、导入和搜索。库级 `FAQConfig` 有索引模式和问题索引模式，默认在 `EnsureDefaults` 中补齐，例如按问答组合索引。导入走维护队列任务 `faq:import`，可含演练模式。克隆和分享时有专门的 FAQ 同步逻辑，避免只复制文档型知识的假设。

检索时，FAQ 可以优先命中或直接回答，聊天管线中有 FAQ 合并与相关测试，智能体预设 `rag-qa` 默认打开 FAQ 优先。这与“把问答对写进普通文档再靠向量碰运气”是不同的产品路径，更适合客服话术、标准答疑、政策问答这类问题形态稳定的场景。它与普通文档检索有重叠：同一句话可能既在手册分块中，又在 FAQ 条目中。企业通常用 FAQ 承接高频标准问，用文档库承接需要上下文的长资料，而不是只选一种。删除问题、重新生成相似问等操作落在分块的 questions 接口上，说明 FAQ 与生成问题功能也有交叉，但 FAQ 条目是一等公民，生成问题只是普通分块上的附加字段。


## 十三、智能体、技能与沙箱

智能体决定一次对话使用哪些工具、哪些知识库、哪套提示词和哪些模型槽位。界面入口是 `/agents` 列表与编辑，设置里还有沙箱和技能分节。API 在 `routes_agent.go` 与基础设施里的 `/sandbox-configs`、`/skills`：智能体的 CRUD、复制、工具列表、类型预设、分享，以及技能目录、安装、文件、指导语、进度与停止。内置智能体由 `config/builtin_agents.yaml` 提供，包括快速问答、智能推理、数据分析师、维基问答、维基修订、技能安装器和 WeKnora 助手。类型预设由 `config/agent_type_presets.yaml` 提供，例如 `rag-qa`、`wiki-qa`，用于在“智能推理”模式下预填提示词、工具白名单和知识库能力过滤；用户仍可改掉任何预填值。默认的工具驱动模式还会根据已选工具在前端推导知识库过滤，避免预设与工具列表两套真相。

知识问答智能体适合证据型回答；数据分析师适合对 CSV/Excel 做受控 SQL（DuckDB）；Wiki 类智能体适合在页面间跳转和修订；技能安装器用于把技能包装进沙箱；助手面向产品自身的配置与操作，结合当前页面，但仍走授权。自定义智能体可以限制允许的工具、绑定知识库选择模式、是否保留检索历史、是否优先 FAQ、是否开启记忆等。分享到组织后，其他空间可以使用但受共享权限和“按租户禁用某个共享智能体”控制。执行权限与审批在 v0.9.0 成为明确功能：只读、修改前确认或自动执行，以及有范围的授权记录，防止助手或自动化以用户身份做超出预期的写入。

技能是安装到沙箱中的指令与脚本包，来源包括目录、上传包和文档中列出的远程来源。设置里的技能分节要求 Admin，因为安装会改写该沙箱配置所启动的环境。技能有文件、指导语、安装事件、转写和停止接口。环境变量分用户级与空间级，凭证应走保险库或专用字段。沙箱后端可以是 Docker、E2B、CubeSandbox，Lite/桌面则走本机沙箱（文档写明桌面目前以 macOS Seatbelt 为说明范围）。远程沙箱在 Lite 中被部署能力标为不支持。会话可以申请终端或桌面票据，打开可视化面板，并记录活动；后台长命令有独立工作项和取消接口。网络策略限制沙箱出站。按用户复用沙箱可以减少冷启动，释放接口用于回收。企业把技能用于“在隔离环境里跑内部脚本、生成文件或调用受控网络”，而不是在 `app` 进程里直接执行不可信代码。不需要工具执行的部署，可以不启用 Docker 沙箱，只使用检索类工具。

协作、steer、挂起恢复、制品收集属于智能体运行时的体验功能，已在架构文档中说明其机制。对功能评估而言，它们让长任务和多人审批成为可能，也要求管理员理解：一次自动化或助手运行可能创建委派子会话，并在等待审批时保持挂起。

## 十四、MCP

MCP 在 0.9.0 里有两个方向，不能混用一个开关描述。

作为客户端，空间管理员在设置的 MCP 分节登记外部 MCP 服务，填写端点与凭证，测试连接，刷新工具与资源元数据，配置按工具的审批，并处理 OAuth 授权、状态查询和注销。API 在 `/mcp-services`。智能体或助手在对话中调用这些工具时，可能弹出审批或要求用户完成 OAuth，会话路由为此提供决议和取消接口。这适合把公司已有的 MCP 工具（工单、日历、内部检索）接到 WeKnora 的智能体上，而不把那些系统的协议写进主代码。

作为服务端，空间可以创建对外 MCP 端点（`/mcp-endpoints`），配置工具白名单和知识库范围，轮换令牌，然后让 Claude、Cursor 等客户端连接 ` /mcp/:endpoint_id`。Viewer 可看列表和工具目录，Admin 才能改。这适合“把本空间的检索和问答能力交给外部编码助手或对话产品”，范围由端点而不是由对方账号在 WeKnora 里的角色决定。工具箱里有 MCP Server 集成说明页，对应这一方向。

仓库根目录的 `mcp-server/` Python 服务和 Compose `full` 里的 `mcp` 容器是旧实现，官方文档标明弃用，新部署应使用内置端点。继续运行旧服务只会增加一套用 REST 再包一层的重复入口。API Key 管理 MCP 服务和渠道的能力是分开的：登记外部工具用 `manage_mcp_services`，对外端点与 IM/嵌入渠道用 `manage_channels`。

## 十五、多模态、语音与图片检索

多模态不是默认核心。文档中的图片可以在解析时抽出，进入画廊；若开启多模态后处理，会生成 OCR 文本块、描述文本块，并可能生成图片向量块。聊天里上传的图片，在对话模型不具备视觉能力时，可以把描述拼进用户消息；具备视觉能力时由 VLM 直接理解。知识库的 VLM 配置和是否启用多模态是库级选配，单次上传可覆盖。校验要求：上传图片需配视觉模型，多模态可能要求对象存储完整。`image_vector` 块的索引是图片向量，重建文本索引的路径不能处理它，这是功能限制，不是文档笔误。

语音方面，音频入库和 `POST` 会话转写接口依赖 ASR 模型。未配置时，相应入口应被拒绝或不可用，而不是用对话模型去“猜”音频内容。企业里的会议录音、培训视频字幕，属于打开 ASR 之后的场景；纯文本知识库不必配置。

与“在 PDF 解析阶段做 OCR”相比，多模态后处理更偏“对抽出的图片再理解一遍”。两者可能同时存在，因此会出现解析器已经识别了扫描件文字、后处理又对同一页图做描述的重叠。关闭不需要的后处理可以节省模型和存储。智能体与会话的图片工具、画廊检索，都建立在这些块类型之上。

## 十六、数据源同步

数据源把外部系统的资料周期或手动同步进某个知识库，避免业务人员反复下载上传。界面在库设置的数据源页，包括编辑、同步日志和类型图标。API 在 `/datasource`：类型、校验凭证、CRUD、同步设置补丁、同步、暂停、恢复、日志、资源列举和祖先查询。支持的连接器类型包括飞书、Lark、飞书云盘、Lark Drive、Notion、Confluence、语雀、GitHub、Google Drive、OneDrive、钉钉、网页爬取、Slack、IMAP、RSS、GitLab、腾讯 IMA、Seafile、Nextcloud。同步模式为增量或全量，冲突策略为覆盖或跳过，可以配置是否同步删除，以及 cron 调度。状态有激活、暂停、错误、删除。每次执行写同步日志，任务类型为 `datasource:sync`。

这是典型的企业选配：制度在语雀、设计在 Notion、代码说明在 GitHub、云盘在飞书或 Seafile，各用对应连接器，最终仍变成同一知识库中的知识对象。凭证加密保存，并有单独的凭证接口，避免普通更新误传密钥。SSRF 与外部 API 速率限制（例如飞书相关的每分钟请求与重试等待）会影响稳定性。暂停和冲突跳过用于避免同步覆盖人工修订。数据源替换知识对象时有原子软删除旧行的路径，删除计划会识别这种情况。不需要外部同步的空间完全可以只用上传。网页爬取与 URL 单次导入有重叠：前者是带调度和游标的连接器，后者是一次性知识创建。

## 十七、联网搜索

联网搜索为问答或智能体提供知识库之外的网页证据。界面在设置的“联网搜索”，会话或智能体上有是否启用的开关。API 包括 `/web-search` 测试与提供方 `/web-search-providers` 的 CRUD、凭证和测试。提供方可为 SearXNG、Tavily 以及文档中列举的 Bing、Google 等，按租户保存并指定默认。Compose 的 `searxng` profile 提供自建元搜索，默认绑定回环 8888，需注意与其他本机服务的端口冲突。管线在启用时于重排之后插入网页抓取阶段，并把结果做成 `web_search` 类型的检索块参与融合。智能体还可以把搜索作为工具使用。

对企业，联网搜索适合“内部资料不足、需要公开网页补充”的场景，例如竞品公开信息和官方公告。有保密要求的空间应保持关闭，以免查询词出站。它与知识库检索、图谱检索并列，是第三条证据来源，默认关闭。压缩和过滤相关服务用于控制抓取结果进入提示词的体积。

## 十八、即时通讯与嵌入渠道

IM 把微信、企业微信、飞书、钉钉、Slack、Telegram、QQ 机器人、Mattermost、云之家等平台的消息接入同一个智能体或知识范围。界面挂在智能体下的 IM 渠道，以及部分平台的二维码或回调配置。API 包括渠道 CRUD、开关、回调、微信二维码状态。渠道配置绑定智能体、可选知识库、传输模式、输出模式、会话模式、机器身份、凭证和语言。入站消息有长度和附件上限，出站会去掉仅 Web 可用的引用标签，并按间隔刷新流式内容。平台用户或线程映射到内部会话，以便续聊。钉钉在较新迁移后只用 websocket。未配置的平台不会出现可用渠道，不必启动额外的 IM 中间件进程，适配器在 `app` 内运行。

嵌入渠道把精简聊天框放到外部网站。接口包括渠道 CRUD、轮换令牌、预览会话、统计，以及公开的令牌交换、配置、建议问题、会话和问答入口。前端有独立的 `embed` 入口和来源策略。限流按 IP、渠道每分钟和渠道每日分级。适合把“对某产品文档提问”嵌进文档站或企业内部门户，而不开放完整工作空间。令牌泄露的风险高于普通登录，因此轮换和域名限制是功能的一部分，不是可有可无的装饰。

两者都是入口选配，核心问答不依赖它们。它们与 API、CLI、MCP 端点一起，构成“同一知识库，多种提问表面”。企业应按调用方选择：内部员工用 Web，客服用 IM，公开文档用嵌入，开发工具用 MCP 或 API Key，而不是为每种表面各建一个库。

## 十九、长期记忆

长期记忆跨会话保存用户或主体的偏好与事实，在后续问答中召回。默认按配置关闭或需在设置中打开。用户在“我的记忆”中查看条目、确认或拒绝、管理主题、导出和触发整理；Admin 在空间记忆分节管理空间策略，并可以管理无账号主体的记忆。API 在 `/memory` 与 `/admin/memory/subjects`。抽取任务 `memory:extract` 在会话轮次防抖后进入 enrichment 队列，使用对话模型。召回发生在问答管线前部的 `MEMORY_RECALL`，还有亲和性插件调节记忆与当前问题的关系。智能体可以按配置关闭记忆，以免把个人记忆带进不该出现的共享智能体回答。

适合需要“记住我的项目名称或常用口径”的个人助理场景。高共享、高合规的制度问答空间可能应关闭记忆，或只允许用户管理自己的条目，以免把个人信息写进空间级上下文。记忆与聊天历史不同：历史是会话内轮次，记忆是跨会话提炼后的条目，确认/拒绝流程说明它被当成可能出错的抽取结果，而不是绝对事实。

## 二十、自动化与 WeKnora 助手

这两项是 v0.9.0 明确写出的新增能力。助手是内置智能体，用于解答版本、功能与配置问题，结合当前页面，并以用户身份检索资料、执行已授权的操作。界面通过助手入口和带 `assistant` 种类的会话提供，普通聊天列表不把助手会话与日常问答混在一起。它仍然经过角色与资源授权，不能因为它“能看当前页”就获得 Owner 权限。

自动化在 `/automations` 管理。API 包括创建与更新、触发校验、暂停与恢复、手动运行、查看运行、授权候选人与授权记录、取消运行，以及通知已读。调度器按一次性或周期计划，以任务所有者身份启动助手会话，并保存运行记录和站内通知。权限与审批复用智能体的执行授权：只读、确认后修改或自动执行。部署上需要考虑调度并发和模型容量，官方功能文档单独提到容量与限制。适合周期性汇报、定期检查知识库健康、按计划运行助手工作流等企业事务，而不是替代数据源同步（同步仍应走连接器）。没有审批策略就把自动化设为自动执行写操作，会放大误操作范围。


## 二十一、评测

评测用来比较不同分块、模型和检索配置的效果，而不是给最终用户使用的问答界面。官方功能文档写明：暂时没有独立的界面入口，通过 `POST /api/v1/evaluation` 发起、`GET /api/v1/evaluation?task_id=...` 轮询结果；创建需要 Admin，查询需要 Viewer；API Key 还需要 `run_evaluations` 或全权限。服务从工作目录 `./dataset/samples/`（容器内 `/app/dataset/samples/`）加载五个 Parquet 文件：问题、语料、参考答案、问题与段落的相关性、问题与答案的映射，拼装为 `QAPair`。`dataset_id` 目前只用于组成任务 ID，不会切换到其他目录；自定义数据必须按同一 schema 替换这些同名文件。任务会参考某个知识库的配置，但导入语料到单独的评估库，以免污染业务库。完成后给出 Precision、Recall、NDCG、MRR、MAP、BLEU、ROUGE 等检索与生成指标。比较时应固定数据集、每次只改一个变量。

这是面向算法与配置负责人的选配能力。没有界面，意味着一般空间成员不会在导航里看见它。企业若要做回归评测，需要把数据集挂载进容器，并用具备权限的 API Key 跑任务。它依赖对话模型，通常也依赖重排模型（创建参数里选择），以及能够写入评估库的入库路径。它不是线上流量的 A/B 平台，也不替换 Langfuse 上的调用追踪。

## 二十二、可观测性、队列与追踪

对管理员可见的运行观测，首先是系统设置中的队列页（`system/queues`）和任务检查器 API：查看队列积压、死信、按知识库取消、重放失败任务。处理跨度让单篇文档的解析、分块、嵌入耗时和错误可查。系统信息提供版本、发行、数据库迁移版本或 dirty/失败、图谱引擎是否启用、对象存储是否配置、进程启动时间。解析引擎、存储引擎、沙箱和模型目录另有探测或预览接口。审计日志在空间级和系统级可查，并按保留天数清理，记录成功或拒绝的操作。这些是标准发行里就有的管理功能，不需要额外 profile，但死信和队列细节依赖 Redis 与 Asynq。

Langfuse 是选配的模型调用追踪。可以只填 `LANGFUSE_HOST` 与密钥指向外部实例，也可以用 `langfuse` profile 自建 Web、Worker、ClickHouse 和专用 MinIO。它跟踪聊天、嵌入、重排、视觉、语音等调用和 token 消耗，与评测指标、审计日志的职责不同：审计看谁做了什么，评测看配置好不好，Langfuse 看模型调用细节和费用。不启用时，核心问答不受影响。日志本身支持级别、路径、格式和 LLM 调试转储等环境变量，属于运维调参。

## 二十三、存储后端与文件访问

默认本地磁盘存储即可完成上传、预览和下载。设置中的存储引擎分节允许登记 MinIO、腾讯云 COS、火山引擎 TOS、AWS S3、阿里云 OSS、华为云 OBS、金山云 KS3 等，并把某个后端设为空间或知识库默认。API 在 `/storage-backends`：类型、测试、校验、CRUD、设默认。知识库还可以单独绑定存储，初始化向导也能写入该绑定。统一资源表为文件分配短句柄，预签名下载与预览、`/r/:token` 短链、知识下载和批量下载都走授权与过期控制。聊天附件可以是临时生命周期，到期且无引用后清理。配额在租户上以存储配额和已用量约束，超出应在入库时失败。

对象存储是选配，但某些图片多模态校验会把它当成前置条件，这是“功能可选、一旦打开就产生新的硬依赖”的例子。文件访问策略还包括允许列表、SSRF、预览安全测试中覆盖的路径穿越与权限。对企业，合规往往要求文件落在指定的云桶或内网 MinIO，而不是容器本地卷；此时应在上线前配好后端，再导入资料，以免事后迁移遗漏资源绑定。向量存储与对象存储职责不同，不能把 Qdrant 当成文件桶，也不能把 S3 当成检索引擎。

## 二十四、平台管理与系统设置

平台管理面向系统管理员，入口在 `/platform` 与 `system/settings`、`system/admins`、`system/queues` 等。能力包括：查看和修改全局系统设置、维护模型目录、查看运行队列、管理平台 API Key、查看全局审计、列出用户、调整用户状态、重置密码、创建用户、提权与撤销系统管理员。引导环境变量可以在尚无系统管理员时提升指定邮箱，一旦已有管理员即不再授权。工作空间管理员则管理本空间的成员、默认模型槽位、配额范围内的资源。两者不要混淆：空间 Admin 不能代替系统管理员改模型目录或平台密钥。

注册策略、密码复杂度、每用户空间数、默认配额、邀请策略、审计保留、跨租户访问等，属于部署级或系统设置级功能，影响所有空间。解析引擎与存储引擎的连通检查，帮助管理员在向导阶段发现配置错误。这些功能是私有化企业部署的治理面，单人 Lite 使用时大多用不到，但标准 Compose 的多用户场景应当在上线时先确定谁是系统管理员，并轮换密钥。

## 二十五、客户端与其他集成

Web 前端是默认客户端。除此之外，仓库还提供：

`cli/` 独立命令行，可管理知识库、文档、检索、会话、智能体、模型、MCP、技能，并提供 `doctor` 诊断，适合脚本化和运维排障。`client/` 是 Go SDK，供二次开发把 API 嵌进内部服务。`miniprogram/` 是微信小程序客户端，用于移动端提问，而不是管理配置。`cmd/desktop` 是 Wails 桌面包装，文档写明尚未作为正式发布，需自行构建，并与 Lite 存储模型相关。Chrome 扩展、本机浏览器技能、Claw Skill、DeepSeek Harness 插件（`packages/dsh-weknora`）分别把浏览、外部助手生态和特定 IDE/Harne​​ss 接到同一 API 或 MCP 面。工具箱页面为 CLI、API、MCP、扩展和 Claw Skill 提供说明与配置入口。

这些客户端都是选配表面，不增加新的知识模型。企业按员工工作习惯启用其中几个即可。已弃用的 Python MCP 服务不应再作为推荐客户端接入方式。腾讯云轻量模板或微信对话开放平台的在线使用若只出现在宣传或外部文档、而不在本树运行时配置里作为可开关组件，则不属于这次源码对照能保证的本机功能，本文不把它写成与 Compose 并列的已实现部署模式细节。

## 二十六、重叠、冗余与“看起来可选其实被绑住”的情况

0.9.0 里确有多条路径在做相近的事，需要按场景选择，而不是全部打开。

检索证据可以同时来自向量、关键词、FAQ 条目、Wiki 页面分块、图谱邻接分块和联网搜索。它们共享融合与重排，因此重叠是有意的，用来提高召回；代价是重复内容和费用。只开向量加关键词，已经覆盖默认核心。FAQ 与“在文档中写问答再检索”重叠，但 FAQ 有稳定的条目模型和优先命中策略。Wiki 与文档检索重叠，但 Wiki 提供可浏览修订的门户。图谱与关键词里搜实体名重叠，但图谱能沿关系跳到未直接共现的分块。联网搜索与数据源里的网页爬取重叠：前者服务当次问答，后者把网页变成库内知识。URL 单次导入又与网页爬取重叠，差别是一次与持续。

问答入口有知识问答、智能体问答、混合检索 API、MCP 端点、IM、嵌入、CLI 和 SDK。生成答案的引擎仍是同一套模型和检索总线，差别是工具、鉴权和事件格式。内置 MCP 端点与弃用的 Python MCP 服务是历史重复，只应保留前者。环境变量向量库与库表向量存储是两套登记方式，运行时可以并存，配置者要知道谁是知识库实际绑定的那一个。`ExtractConfig.Enabled` 与 `IndexingStrategy.GraphEnabled` 是历史双字段，运行时以合取为准，加载时会做同步。`Pipeline` 固定表与 `PipelineBuilder` 动态装配并存，真正的知识问答走后者。`ENABLE_GRAPH_RAG` 已被忽略，只认 `NEO4J_ENABLE`。

被绑住的“假可选”包括：类型层在开启关键词时仍要求嵌入模型；图片多模态可能强制对象存储；打开图谱却未部署 Neo4j 时，抽取可能空耗模型；`config.yaml` 默认打开改写和重排，但没有重排模型时不能当成已经具备重排效果；关闭 RBAC 时角色守卫放行，多租户隔离不能再按界面角色来假设；Lite 关闭组织与远程沙箱，不是设置里能再打开的选配。这些都不否定“功能很多、多为选配”的总判断，只是要求在打开某一开关前读依赖，而不是假设每个开关都是完全正交的。

解析侧，默认 docreader、OpenDataLoader 混合、以及文档中出现的其他引擎，是为不同版式准备的可替换实现，同时开多个并不会自动提高质量，需要按文件类型指定规则。模型侧，用途绑定允许为抽取和问答配置不同实例，也可以全部指向同一对话模型，后者更常见，前者才是真正的多模型策略。客户端再多，也不应理解成多套权限系统：它们最终都落到 JWT、API Key、渠道令牌或 MCP 端点令牌之一。

## 二十七、限制、标志与默认关闭的路径

部署级关闭或默认关闭的重要标志包括：`NEO4J_ENABLE`（图谱）、`OIDC_AUTH_ENABLE`（单点登录）、`DISABLE_REGISTRATION`（关闭公开注册）、`WEKNORA_TENANT_ENABLE_RBAC`（关闭则守卫放行）、`WEKNORA_TENANT_ENABLE_CROSS_TENANT_ACCESS`（跨空间访问）、`WEKNORA_TENANT_SELF_SERVICE_CREATION_ENABLED`（自助建空间）、`OLLAMA_OPTIONAL`、`WEKNORA_SANDBOX_DOCKER_ENABLED`、`WEKNORA_HOUSEKEEPING_ENABLED`、`LANGFUSE_ENABLED` 及相关密钥、各 `RETRIEVE_DRIVER` 与 `STORAGE_TYPE` 取值、数据源与联网搜索是否配置。知识库级默认关闭 Wiki 与图谱，默认打开向量与关键词。多模态、ASR、重排、问题生成、自动标签、画像、记忆、自动化，都要显式配置或在界面打开才会进入日常路径。

资源限制方面，类型与配置中可以看到：分块大小上下限、父子块大小上限、上传体积 `MAX_FILE_SIZE_MB`、技能包体积、FAQ 与混合检索等请求体限制、嵌入聊天体限制、图查询请求 8KiB 与结果截断、IM 消息 4096 长度与附件 32MiB（视觉附件更小）、预签名与令牌过期、存储配额、模型并发、Asynq 各池并发、文档处理超时、对话附件 TTL、Wiki 修订保留的软硬上限、审计保留天数、公开注册接口的每 IP 速率。评测数据集路径写死为 `dataset/samples/`。这些限制是功能边界的一部分：超过就应失败或截断，而不是悄悄丢数据。精确数值以对应类型标签和环境变量注释为准，部署时不要在未核对源码的情况下假设“没有上限”。

Lite 与桌面还限制组织、远程沙箱和自动开户的可用范围。Helm Chart 默认只覆盖核心组件加可选 Neo4j，并不自动安装全部 Compose profile。MySQL 不是主库选项。Infinity 与 ElasticFaiss 不是可采购引擎。

## 二十八、本版本明确不包含或不再推荐的事项

源码和仓库文档已经标明的范围外或不再推荐项，包括：主应用不再读取 `ENABLE_GRAPH_RAG`；飞书云文档旧解析模式变量仅作短暂兼容，新路径用数据源连接器；独立 Python `mcp-server` 已弃用，改用内置 MCP 端点；`migrations/mysql` 未接入启动，不能当作支持 MySQL 主库；桌面应用尚未作为正式发布形态；评测没有独立 Web 界面，且不能通过 `dataset_id` 切换目录；类型中的 Infinity/ElasticFaiss 无独立可部署实现。Wiki 不是 Neo4j 图谱。评测不是在线实验平台。助手不能绕过授权。关闭 RBAC 不是推荐的生产权限模式。

本文也不把未在 0.9.0 源码树中实现的能力写成规划功能，例如不存在的第六类模型、不存在的默认 Helm 全家桶、或未出现的独立“企业工作流引擎”（自动化是助手调度，不是通用 BPM）。若上游后续版本增加能力，需要重新对照，不能直接沿用本文的开关表。

综上，WeKnora 0.9.0 的功能面确实很宽：默认路径是空间内的文档库加混合检索问答，其余大量能力按模型、进程、库开关和角色组合叠加，从而覆盖客服 FAQ、制度门户、关系型知识、外部知识同步、多渠道接入、工具执行和治理评测等不同企业场景。使用上的要点不是把功能用满，而是为每个空间选择最小够用的一组选配，并分清重叠路径中哪一条是该场景的主入口。

## 二十九、角色与邀请中容易判错的能力边界

成员与角色的粗分前面已经列出，这里补上源码和官方权限文档里几处直接影响企业分工的细节。会话和问答对 Viewer 开放：Viewer 可以创建自己的会话、发起知识问答和智能体问答，只是不能创建知识库或智能体。把 Viewer 理解成“什么都不能建”会与实现不符。相反，成员的增删改角色和发送邀请在路由上挂的是 Owner 守卫，Admin 也不能做这些事；Admin 可以管理集成和空间级基础设施，但把“人事权”留在 Owner。这与许多企业套件“Admin 等于除删除租户外的一切”不同，分配角色时必须单独交代。列表邀请对 Viewer 可见，撤销邀请链接则是 Owner 操作。

资源变更还受所有权约束。有创建者的资源（知识库、智能体、知识对象、分块、Wiki 页面、FAQ 条目、标签）修改时，常用“所有者或 Admin”守卫；没有创建者的租户级基础设施（模型、向量存储、IM 渠道、联网搜索提供方、数据源、MCP 服务）由 Admin 管理；创建尚未存在的资源需要 Contributor。复制智能体只给自己一份副本，Contributor 即可；把知识库共享到组织或禁用全空间可见的共享智能体，则要更高的公开副作用守卫。组织分享里还有一层压缩：即使分享侧授予了编辑权限，若调用者在本空间只是 Viewer，有效权限会被压到 Viewer，避免用分享通道绕过本空间只读角色。

这些规则决定了企业里如何划分“空间负责人、业务编辑、只读专家、集成管理员”。集成管理员往往应是 Admin 而不是 Owner，以免掌握邀请权；只读专家用 Viewer 即可提问；业务编辑用 Contributor 管理自己创建的库。若关闭 RBAC，上述区分在守卫层失效，只剩日志，不能再按这张矩阵做合规承诺。

## 三十、会话体验中的附加功能

除流式回答和引用外，会话页还包含一组影响日常使用但不改检索引擎的功能。助手与自动化运行可以在界面上展示任务进度和挂起等待，用户不必到队列页才能知道“还在跑还是在等审批”。回答过程中可以补充要求（steer），也可以调整思考强度，后者对应模型用途或会话配置里的推理预算，并不是单独一类模型。消息中的提及可以把知识库或对象标进这一轮检索范围，后端用 `SearchTargets` 参与是否走 RAG 的判断。用户可以把某一轮回答存入知识库：界面提供标题、目标库、Markdown 编辑、草稿与正式入库，这是“从对话沉淀知识”的路径，与数据源同步、上传文件并列，适合把已经确认的答复写回 FAQ 或文档库。实现上它仍会创建知识对象并进入入库或手工知识更新，而不是绕过解析状态机。

长对话提供提问目录、时间分隔和按发送时刻显示的时间；侧栏会标出本浏览器中仍在生成的会话，并为 API 调用方做标记。会话可以复制为 Markdown，在浏览器本地生成含标题、ID、导出时间和逐轮问答（含附件与引用）的文本，用于归档。侧栏搜索可跨会话找历史消息。空间管理员在消息管理中启用消息索引并选择嵌入模型后，搜索可叠加语义匹配；未启用时走关键词。已有索引时不能直接更换嵌入模型，关闭开关也不会删除已有索引数据；更换模型需要清空索引并确认，该操作会暂停自动索引并清除当前空间所有成员的历史消息检索索引，但保留原始消息，也不影响普通知识库检索。这是不可撤销的空间级操作，必须由 Admin 执行，且要让成员知道“会话搜索会暂时退回关键词”。渠道会话可以在界面中查看，便于客服回看 IM 或嵌入里发生的对话，其主体和权限仍受渠道范围约束。

附件提问使用临时文档任务，配置包括等待超时、OCR 并发和页数上限等。生成的文件在会话或制品库中预览下载。分叉与回滚改变会话历史截点，适合比较两种问法，但会增加会话行，不自动删除原会话。这些体验功能大多在标准 Web 客户端中可用；IM 和嵌入只会保留其中能在外部平台表达的子集，例如 IM 会去掉 Web 专用引用标签。

## 三十一、智能体工具清单与“不能靠勾选关掉”的工具

智能体的可选工具定义在 `internal/agent/tools/definitions.go`，并分组。基础组包括思考（`thinking`）、制定计划（`todo_write`）、向用户提问（`ask_user`）。RAG 组包括检索知识库、阅读文档、浏览文档列表、查询知识图谱、查询数据库。会话与记忆有搜索对话、搜索记忆。数据组有数据分析与查看数据元信息。联网有 `web_search` 与 `web_fetch`。Wiki 读组有搜索与读取页面，写组有写页、替换文本、重命名、删除，问题组有标记、查看和更新问题。读文件（`read_file`）在工作区、技能资源和会话附件之间统一，注释写明用户刚上传的附件不能被白名单藏起来。

有一批工具故意不出现在租户可编辑的工具清单里，以免勾选框撒谎。沙箱文件的列表、写入、编辑以及 `shell_exec`、异步 Shell，跟随着沙箱或技能开关以及后端是否具备会话工作区能力（Cube、E2B、Docker）注册，而不是跟随着智能体上的工具勾选；关掉勾选也不会改变它们是否存在。技能安装器专用的技能文件写入工具只在安装模式授予，作用于共享快照镜像，不能变成普通自定义智能体上的可选项。MCP 的发现与调用是能力范围内的动态工具，也不是租户勾选的内置名。安全表单和浏览器填密工具用于沙箱浏览器，智能体只能得到句柄而不能得到密文。这些设计防止“界面上取消了 Shell，实际因为开了技能还在跑命令”一类的误解。企业在审查智能体风险时，应同时看工具白名单、技能开关、沙箱后端和 MCP 登记，而不是只导出一张勾选列表。

图谱查询工具依赖库的图谱能力与 Neo4j；Wiki 工具依赖 Wiki 能力；数据分析依赖表格类资料和 DuckDB；联网工具依赖提供方配置。预设会按工具推导或显式声明知识库过滤，避免把 Wiki 修订智能体绑到没有 Wiki 的库上。已更名的旧工具名有后继映射，以免历史智能体配置失效。默认的 `rag-qa` 预设有意不包含思考和待办工具，以免单轮问答浪费 token，需要时再手动打开。这些都是功能上的默认策略，不是架构限制。

## 三十二、解析引擎选择与 PPT 默认回退

当知识库没有为某文件类型配置 `parser_engine_rules` 时，`DefaultParserEngine` 返回空字符串，表示走内置 docreader 或 Go 侧简单格式路由。例外是 `ppt` 与 `pptx` 默认映射到 `markitdown`，因为内置简单引擎不能处理它们。若构建链注册了 anydoc 绑定，它可以在 prefer 函数中优先于上述默认，对所支持的类型生效（Go 简单格式除外）。聊天附件另有智能体级的 `ChatParserEngineRules`，通过上下文键作用于临时文档解析，使会话附件与知识库入库可以使用不同引擎规则。设置里的解析引擎页和系统的 `GET /parser-engines`、`POST /parser-engines/check` 用于查看和探测可用引擎，包括可选的 OpenDataLoader、云端或外部引擎，具体出现哪些引擎取决于该部署的编译绑定与配置，而不能假设每个官方提到的名字在当前二进制里都已连接。

企业处理大量幻灯片时，应意识到默认已经走 MarkItDown，而不是“未配置即内置 PDF 同类引擎”。对扫描件或复杂版式 PDF，再为 `pdf` 单独写规则指向混合或 OCR 引擎。规则按文件类型列表匹配，未命中则回退默认。引擎配置中的密钥在 API 响应里会脱敏，更新时有保留语义，避免为了改规则而重交全部密钥。

## 三十三、按企业场景组合能力的建议读法

把前面的选配落到常见企业场景时，可以用“主入口加最小依赖”来读，而不是按菜单逐项打开。

内部规章制度问答：一个或几个文档型知识库，默认向量加关键词，对话模型和嵌入模型，Web 会话。按需加分块策略调整和重排。不必开图谱、Wiki、数据源、IM、沙箱。权限上用 Contributor 维护制度，Viewer 查询。

客服标准问：FAQ 类型库加文档库，FAQ 优先，嵌入渠道或企业微信/飞书渠道接到只读智能体。API Key 只给 `chat` 与 `retrieve`，并限制知识库 ID。不要把客服机器人做成空间 Admin。

研发知识与代码说明：GitHub 或 GitLab 数据源同步到文档库，智能体启用阅读文档和检索；若允许在沙箱里跑只读脚本，再开技能。生产密钥走凭证库。联网搜索通常关闭。

产品与组织关系资料：打开图谱和 Neo4j，抽取用对话模型，问答走并行实体检索；可用图查询接口做排查。不必为此改 FAQ。

需要知识门户：打开 Wiki 自动生成或只手工编辑，配维基问答/修订智能体，并接受与原文分块的重叠及加权调节。

把 WeKnora 接到开发工具：创建对外 MCP 端点，白名单检索类工具和指定库，轮换令牌；不要再部署已弃用的 Python MCP 容器。

周期运营：用自动化调度助手做健康检查或汇报，审批策略至少对写操作设为确认后执行，并查看通知与运行记录。

效果对比：用评测 API 和固定 Parquet 数据集，每次只改分块或模型之一；用 Langfuse 看费用，用队列页看失败任务。

以上组合都建立在同一套核心之上。场景越多，越要避免在同一个库上打开全部富化，以免入库变慢、重复索引变多、排障时说不清证据来自哪一条路径。

## 三十四、知识对象管理的其它操作面

列表与详情之外，还有一批日常会用到、但容易被当成“隐藏功能”的操作。批量下载原始文件需要写或至少有下载授权，走存储后端而不是把内部路径交给浏览器。批量打标签、按文件夹整理、在库之间移动，适合资料治理运动，移动是异步任务并有进度查询，期间对象可能处于过渡状态。复制知识库用于给新部门一个起点，但模型绑定、分享关系和数据源凭证是否一并复制，要以复制服务的实现为准，不能假定“连密钥和外部同步游标都完整克隆”。手工编辑摘要、浏览分块、按块更新图片，用于修正解析错误，而不必整篇重解析。重新生成某块的问题，用于改善用生成问题辅助检索的效果，它与 FAQ 条目不同，不会单独出现在 FAQ 管理页。

画廊配置决定如何展示抽出的图片。图片检索依赖多模态块。重建索引在更换嵌入模型或修复损坏索引时使用，但必须避开不能按文本重建的图片向量块。取消解析保留已写入内容，删除才进入清理计划。活动流帮助审计“谁导入了什么”，与系统审计日志互补：前者偏知识库业务活动，后者偏权限和设置变更。这些操作的权限都落在知识库写或读守卫上，共享库中的有效角色可能低于分享声明，前面已经说明压缩规则。

## 三十五、配置项与提示词对功能行为的影响

即使不改代码，`config.yaml` 和提示词模板也会改变功能表现。会话默认最大轮数、关键词与向量阈值、重排阈值和 Top-K，决定召回宽窄和上下文长短。`enable_rewrite`、`enable_query_expansion`、`enable_rerank` 的默认真值，使产品在“配了相应模型”时自动更积极地改写和重排；未配重排模型时，不应对外宣称已经具备跨模型重排。fallback 策略在检索为空或生成失败时改口或改走模型，影响用户看到的是道歉话术还是一次无证据的生成，需要产品负责人显式选择。摘要、会话标题、知识库描述、实体抽取、问题生成的提示词都通过模板 ID 指向 `config/prompt_templates/`，更换模板等于更换对应富化功能的行为，而不改变任务类型或队列。图谱抽取模板里的关系类型列表限制了允许的关系，超出列表的关系在提示词层面被要求不要提取。

租户默认设置可以把上述槽位和默认模型变成空间级标准，减少每个库重复配置。知识库再覆盖分块和开关。单次上传最后覆盖。理解功能“实际怎么表现”，要沿着这层覆盖看，而不能只读全局配置文件。提示词和阈值调优属于功能配置，不是开发扩展，但它们对效果的影响往往大于再加一个向量库。

至此，0.9.0 的功能说明已经覆盖源码中存在的主要领域、入口、依赖、默认开关、重叠路径和明确不在范围内的事项。与 `architecture.md` 对照阅读时，前者回答“系统如何分层和流转”，本文回答“开哪一项、给谁用、缺了什么会怎样”。二者依据同一提交，均未启动运行栈，也未向 GitHub 推送。

## 三十六、命令行客户端能做什么

`cli/` 是独立的 `weknora` 命令行，面向运维、脚本和自动化代理，而不是替代 Web 管理的全部页面。根命令登记的子命令包括：认证、配置与多profile、把当前目录链接到某个知识库、知识库、文档、分块、搜索、聊天、会话、消息、智能体、模型、MCP、技能、通用 API 调用、以及 `doctor`、版本、退出码和 schema 说明。快速路径是：登记并激活一个服务器 profile，用交互密码或从标准输入管道传入 API Key 完成认证，列出知识库，把目录绑定到某个库后上传文档并等待解析结束，然后搜索或向模型流式提问。还可以检查文档分块以调试检索，查看会话消息或跨会话搜索，以及在智能体运行停在工具审批时提交决议。

多 profile 允许同一台机器指向多个 WeKnora 部署。Dry-run 可以预览例如创建知识库的计划而不真正执行，输出带 `dry_run` 标记的 JSON，适合在 CI 或人工审核后再跑正式命令。流式输出、JSON 输出和稳定的退出码是为了让其它程序解析结果。它消费的是同一套 HTTP API，权限完全取决于所用的用户或 API Key，不能用 CLI 绕过 Viewer 不能建库的限制。企业把它用在发布流水线里“文档更新后自动入库并等待 completed”，或用在排障时“doctor + 查看分块”，而不是给所有业务人员安装命令行。CLI 不能代替评测 API 的数据集替换，也不能在 Lite 不支持的组织功能上变出新能力。

## 三十七、小程序与其它轻量入口的功能范围

`miniprogram/` 是微信小程序插件式客户端，README 写明它提供轻量能力：配置 API 地址和租户 API Key，在中英文之间切换界面语言，列出知识库，把 URL 导入选中的库，以及通过知识问答接口提问。页面只有设置、知识库列表和聊天，没有空间成员管理、模型目录或数据源配置。聊天消费 SSE，并在小程序里解析累计的 answer 片段。生产环境需要把 API 域名加入小程序合法请求域名；开发工具可能拦截 localhost。这意味着移动端入口被有意做成“提问和简单导入”，完整治理仍在 Web。API Key 应只授予 `retrieve`、`chat`、必要时 `ingest`，并限制知识库，以免手机里一份密钥等于管理员后门。

Chrome 扩展、本机浏览器技能和嵌入页同样是窄入口。浏览器技能让智能体在用户本机浏览器里操作页面，涉及扩展授权、本机连接数和公共 URL 等配置，属于高敏感选配，只应在明确需要“打开内网网页并阅读”的空间打开，并配合安全表单填密，避免密钥进入模型上下文。嵌入页只提供渠道范围内的聊天。桌面构建若使用，还带 Lite 自动开户和本机沙箱，但不能当作已正式发布的通用客户端来规划全员安装。Go SDK 则把这些 API 交给内部服务二次封装，适合做公司自己的门户，而不暴露 WeKnora 完整前端。

## 三十八、即时通讯里的命令与会话控制

IM 适配器除了把自然语言转成问答外，还注册了一组文本命令：`help`、`info`、`search`、`stop`、`clear`。它们让用户在微信或飞书里查看帮助与渠道信息、发起检索、停止生成、清空当前映射会话，而不必回到 Web。命令与普通提问共享同一渠道绑定的智能体和知识范围，不能用来改空间设置或上传任意管理指令。附件和引用长度限制、去重窗口、流式刷新间隔，决定了 IM 上的体验比 Web 更受约束：不适合在群里丢几十兆附件，也不应期望与 Web 完全一致的引用卡片。渠道可以设置固定回复语言，空则用部署默认语言。会话模式决定是按线程还是按用户续上内部会话，配错会造成“每次都像新对话”或“把不同人的上下文串在一起”，这是功能配置问题，需要在上线前用真实平台线程验证。对企业客服群，通常应使用独立的只读智能体和被限制的 API 范围，并关闭联网搜索。

## 三十九、初始化向导作为产品功能

对第一次部署的管理员，初始化向导是功能而不仅是内部 Handler。它按知识库引导配置对话、嵌入、可选的重排、视觉、语音和图谱抽取，探测 Ollama，下载本地模型并查看进度，检查 `NEO4J_ENABLE` 和对象存储是否满足将要打开的选项，并以脱敏后的视图回读当前配置。日常设置页是同一批对象的编辑器，向导是“还没有配齐就不能顺畅问答”时的集中入口。前端初始化模块与设置模块分开，但权威数据都在模型表和知识库行。企业交付时，应把向导走完并保存密钥保管流程，视为上线检查单的一部分，而不是让每个 Contributor 自己填模型地址。

## 四十、文件访问、分享与把对话沉淀回库

文件预览、下载、短链和预签名是知识库与会话共同依赖的功能。用户在 Web 里点击引用中的原文、在会话里打开附件、在外部平台收到改写后的存储 URL，背后都是资源授权而不是公开桶浏览。过期令牌和来源限制用于降低链接转发后的泄露窗口。把回答存入知识库，则是从会话到知识对象的反向路径：确认后的 Markdown 可以成为手工知识或再走解析，适合把已审核的答复固化进 FAQ。它与“记忆抽取”不同，前者是显式发布，后者是自动提炼、还需确认或拒绝。企业应规定哪些回答可以入库、入库到哪个库，以免把未审核的模型输出写进制度库。组织分享知识库时，接收方看到的是能力范围内的检索和阅读，看不到所有者的存储密钥；有效写权限还受本空间角色压缩。这些都是协作功能的一部分，不是额外产品。

## 四十一、凭证、环境变量与本机浏览器

凭证保险库和环境变量页让用户和 Admin 把密钥、目录、内部地址从提示词文本里拿出来。技能和沙箱启动时再解析这些值。本机浏览器技能还需要扩展授权和可选的集群密钥，才能让 `app` 与用户浏览器建立受控连接。这些功能只在需要“自动化访问带登录的内部站点或把密钥交给沙箱脚本”时打开。默认核心问答完全可以不配置它们。一旦打开，就应按最高敏感集成来管理：最小权限的环境变量、定期轮换、以及不要把保险库条目写进可导出的普通设置备份明文中（导出与脱敏接口存在，就是为了减少这种事故）。

## 四十二、再补充几组默认关闭或需显式打开的能力

消息的语义索引默认不随知识库向量索引一起打开，必须由空间管理员在消息管理中启用并选择嵌入模型；清空索引是不可撤销的空间级操作。长期记忆默认不会在未配置时自动抽取。联网搜索默认需要提供方或 SearXNG。图谱、Wiki、FAQ 类型、数据源、IM、嵌入、MCP、技能沙箱、自动化、评测、Langfuse、OIDC、独立向量库、云对象存储，均需显式行动。公开注册可以关。自助创建空间可以关。跨租户访问默认应按锁闭理解，除非系统设置打开并授予对应用户标志。Housekeeping 默认开启（可用环境变量关闭）。改写和重排在全局配置里默认开，但仍受模型是否存在的约束。PPT/PPTX 默认走 MarkItDown。关键词开启时配置层仍要求嵌入模型。这些默认值一起构成 0.9.0 的“开箱行为”：先能问答，再按需变重。

若只记住一张功能地图，应是：核心是带权限的文档库加混合检索问答；选配沿五类模型、四种索引管线、多种外部连接和多种提问表面展开；重叠路径要用主入口来取舍；角色上 Owner 管邀请、Admin 管基础设施、Contributor 管自己的内容、Viewer 可以问。这样使用，才能把“功能很多、适合企业多场景”变成可管理的部署，而不是把所有开关同时打开后的运维负担。

## 四十三、数据源连接器之间的功能差异

连接器共用同一套数据源生命周期和同步队列，但能力和失败语义并不相同，企业选连接器时不能只用“能否连上”来判断。以官方数据源文档中的对比和 Seafile 专篇为依据，可以这样理解几组差异。

飞书与 Lark 共用同一套连接器代码，只按区域选择 `open.feishu.cn` 或 `open.larksuite.com`，类型分别是 `feishu` 和 `lark`；云盘模式则是 `feishu_drive` 与 `lark_drive`。认证是企业自建应用的 `app_id` 与 `app_secret`。Wiki 资源是空间下的节点树，可懒加载。内容在 `blocks`（默认）或 `export` 模式下读取：前者走文档块接口，后者导出为 Office 文件再解析。增量按内容编辑时间比对，并支持删除检测（游标里有、当前树没有则视为删除；部分列举失败时会跳过删除检测，以免误删）。它实现了流式可恢复同步，按节点数或时间做检查点。限流时会读 `Retry-After` 并做有限次数退避。单文档失败会生成带错误元数据的占位条目并继续。升级到本版本时有三处行为变化需要当作功能约束：环境变量 `FEISHU_DOCX_PARSE_MODE` 已废弃，只在数据源未配置解析模式时回退并告警；未配置模式的存量数据源默认从 `export` 变为 `blocks`；迁移会打一次性全量重同步标记，下一次同步会把全部文档重新入库并重新计算嵌入和视觉摘要，完成后标记清除。权限按模式不同：列举空间、读文档块、下载图片和附件需要不同的只读权限，缺哪一项就在哪一步失败。国际版与国内版权限标识相同，但应用互不通用。`base_url` 可以覆盖，以兼容历史上把飞书连接器指向 Lark 域名的存量配置。

Notion 使用内部集成 Token，资源是带父子关系的页面或数据库树，内容转为 Markdown，增量按 `last_edited_time`，支持删除检测，并区分“源端已删”和“用户取消勾选”（后者不报删除）。它不是流式可恢复同步。单页失败记日志并跳过。语雀使用个人或团队 Token，资源是知识库的扁平文档列表，正文为 Markdown，增量按 `content_updated_at`，支持删除检测，单文档失败生成占位条目，并且在拉取详情之间有间隔，以迁就个人 Token 的速率限制。RSS 或 Atom 可以无认证或带自定义请求头，每个 feed 一个资源，用可读性抽取再转为 Markdown，用 feed 信号指纹加内容哈希做双层比对，不支持删除检测（源端本身会滚动淘汰旧条目）。单个 feed 失败算部分失败，全部失败才算整次失败。

Seafile 把文件按「资料库名/库内路径」落入知识库文件夹，来源标签为 Seafile。资料库名在首次同步时写入游标并固定，之后在 Seafile 改名不会改知识库目录，也不会触发重新下载。格式范围与普通上传一致，图片与音频仍分别要求 VLM 和 ASR，未配置时该条目在日志中记为入库失败，不影响其它文件。单文件上限沿用 `MAX_FILE_SIZE_MB`（默认 50 MiB），超限不下载、不截断入库；若调大该值，必须同步调整 `DOCREADER_GRPC_MAX_FILE_SIZE_MB` 并重启 app、docreader 和 frontend，否则会出现“下载成功、解析被 gRPC 拒绝”。指纹由对象 ID、修改时间和大小组成，三者相同则跳过下载；变化则先删后建，解析期间该文档会短暂不可用。开启同步删除时，源端删除会删知识条目，否则只从游标移除。重命名或移出范围按“新路径新文件、旧路径删除”处理，不保留原知识 ID。若勾选的目录本身被删除或改名，本轮报错停止且不产生任何删除，需要重新选择范围。目录列表级失败会保存已完成进度后停止，本轮不做删除。Token 失效会使数据源进入错误状态。检查点在游标变更、发出删除前和结束时保存，中断后从检查点继续。已同步的数据源不能改绑其它 Seafile 资料库，改选会失败且游标不变，必须新建数据源。连接器下载重试和知识库解析恢复是两回事，日志里的入库失败要到知识库侧重试，而不是只重跑同步。

这些差异说明“数据源”是一类功能，不是一个功能。选飞书要准备应用权限和可能的全量重同步窗口；选 RSS 要接受没有删除对账；选 Seafile 要处理好改名、上限和不可改绑。GitHub、GitLab、Confluence、钉钉、IMA、Nextcloud、网页爬取等同样各有认证和资源模型，配置前应读对应连接器说明和权限表，本文不把未逐条核对的权限标识写成清单。调度都走 cron 和 `datasource:sync`，冲突策略、是否同步删除，是所有连接器共享的数据源级开关，但删除检测能力取决于连接器是否实现。

## 四十四、联网搜索引擎与读页分工

设置里可以登记多个搜索提供方实例，智能体或会话按实例 ID 引用。`internal/container/container.go` 的 `registerWebSearchProviders` 当前注册十六种引擎类型，包括 DuckDuckGo、Google、Bing、Tavily、Ollama Web Search、百度千帆 AI 搜索、SearXNG、Keenable、智谱、秘塔 Metaso、Exa、博查 Bocha、Brave、Serply、DeepSeek、SearchApi。是否需要 API Key、是否支持按次传递国家或时效、是否自带读页 API，各不相同。DuckDuckGo 可以无密钥，优先 HTML 再回退 API，并可配代理。SearXNG 是唯一允许租户填写 `base_url` 的引擎，必须通过 SSRF 校验，也是与 Compose `searxng` profile 对应的自托管选项。其余引擎端点在实现中硬编码，租户不能改地址，注释写明这是防止 SSRF 的第一道措施。Google 还需 `engine_id`。部分引擎支持 `extra_config`，例如 Metaso 的资源范围、Exa 是否取正文、Bocha 的时效和摘要开关。Brave、Serply、SearchApi 以 `FilteredSearch` 注册，可在工具调用时带国家或时效参数，取值集合并不与 Bocha 的固定配置相同。DeepSeek 同时注册读页，`web_fetch` 在该提供方下可以改走其 Fetch 接口，查询长度也有上限。

功能上，`web_search` 负责发现来源，`web_fetch` 负责读取选中页面正文。用户直接给出网页时可以只读页；需要实时外部信息时可以先搜索再读页。智能体不再被强制要求先调用 `search_knowledge` 才能联网，是否检索知识库取决于任务和当前工具。知识问答管线里的联网则是在会话或配置打开时于重排后插入抓取阶段。结果有去重和数量限制，数量还受智能体“最大结果数”约束。出站代理只隧道流量，不替换 API 端点，同样过 SSRF。密钥经独立凭证接口写入，响应中不回传。测试连接有“未保存参数试连”和“测试已保存配置”两条，避免先把错误密钥写进库。对企业来说，内网保密空间应不配任何出站搜索；需要公开网页补充时，优先自托管 SearXNG 或公司统一的搜索网关，并认清“端点不可由租户改写”是安全功能而不是缺陷。十六种引擎是可选项清单，不是建议全部配置。

## 四十五、上传体积、解析上限与跨组件对齐

`MAX_FILE_SIZE_MB` 不仅约束 Web 上传，也约束 Seafile 一类连接器的下载。默认 50 MiB 这一数值出现在 Seafile 功能说明中，调大时必须同时提高 docreader 的 gRPC 文件上限并重启相关进程，否则会出现存储层已收下、解析层拒绝的断裂。这是跨进程功能限制，不能只改一个环境变量。技能包另有 `MAX_SKILL_BUNDLE_SIZE_MB`。聊天附件、IM 附件、图查询体、嵌入聊天体、FAQ 请求体各自还有更紧的上限，用途是保护交互路径不被批量导入的尺寸逻辑带偏。企业若要把扫描版大 PDF 作为主力资料，需要把应用上限、docreader 上限、对象存储和超时一起纳入容量规划，并接受解析内存占用上升。

## 四十六、命令行诊断与知识库解析链

`weknora doctor` 用于检查当前 profile 指向的服务是否健康、凭证是否可用，属于排障功能而不是日常入库命令。知识库参数有一条解析链：命令行 `--kb`、目录绑定（`link`）以及 profile 默认值按优先级解析，使在已绑定目录中执行 `doc` 和 `search` 不必每次重复指定库 ID。无状态环境变量凭证面向 CI 和其它代理，不必依赖本机交互式密钥存储。机器可读的退出码和 `weknora exit-codes`、`schema` 便于把 CLI 嵌进自动化。这些是 CLI 作为“功能表面”时相对 Web 多出来的能力，核心业务功能仍然一一对应到 API。不能在 Web 完成的事，例如评测数据集目录替换、系统级模型目录编辑，也不应指望只靠默认 CLI 子命令覆盖；通用 `api` 子命令可以调用任意已授权接口，但那是逃逸舱，不是为每个隐藏接口都做了专用动词。

把连接器差异、搜索引擎清单、体积对齐和 CLI 诊断补进功能说明之后，仍应回到同一原则：先选定场景的主入口和最小依赖，再打开与之匹配的选配。0.9.0 提供的是可组合的企业套件，而不是必须全开的一体化开关。

## 四十七、飞书云盘与飞书知识库不是同一个连接器

`feishu` / `lark` 同步的是 Wiki 空间节点；`feishu_drive` / `lark_drive` 同步的是指定文件夹里的文档和文件。二者共用区域与应用身份模型，但权限和资源选择不同。云盘不需要 `wiki:wiki:readonly`。列举文件夹、下载普通文件需要 `drive:drive:readonly`，缺权时往往报 403 并提示需要先把文件夹分享给应用所在的群。`blocks` 模式还需要 `docx:document:readonly`；`export` 模式则需要 `drive:export:readonly` 才能把文档和表格异步导出。可选权限只增强 blocks 渲染（成员真实姓名、引用标题、画板、内嵌表格转 Markdown），缺失时同步不失败，只把对应内容降级。API 权限和文件夹访问权是两层检查：连接测试通过只说明应用凭据有效，加载资源树才会验证文件夹是否已授权。

配置时必须提供具体文件夹的 `folder_token` 或完整文件夹链接，不能留空表示云空间根目录。增量只在选定资源完整列举成功时，把消失的文件标为删除；子目录列举失败会暂缓检测。开启同步删除才会删掉当前数据源对应的知识条目。全量同步（包括升级触发的全量重同步）仍保留旧游标做删除对账；首次同步没有历史基线，无法检测更早的删除。文档更新时清理 blocks 模式里已消失的附件子项，属于内容更新，不受“同步删除”开关控制。

解析模式按数据源保存在 `settings.parse_mode`，默认 `blocks`，同时影响 Wiki 与云盘连接器。`blocks` 把块转为 Markdown，并在 API 失败、正文为空或超过 30 个图片或画板块时回退导出；图片和画板随父文档关联入库，附件可保留为独立条目并与父文档互相关联，内嵌表格转为文内 Markdown 表。`export` 异步导出后再走普通文档解析，耗时更长，内嵌 file 附件不会随导出保留，电子表格在导出后也无法按表格解析。修改有效解析模式后，下一次同步（含增量）会重新抓取已有 docx；只改其它设置不会触发这种重抓。超过内联图片预算而回退导出时，已经列出的 file 附件仍会单独入库。图片最终能否被检索，还取决于对象存储和多模态索引，而不是只取决于飞书是否下载成功。企业应先用少量文件手动同步，核对日志和解析结果，再打开计划和同步删除。飞书与 Lark 凭据不能混用。

## 四十八、技能目录、安装生命周期与沙箱后端开关

技能由 `SKILL.md`、脚本和资料组成，必须先进入空间目录，再安装到某个沙箱配置，然后在智能体的智能推理模式里选用。界面入口已收到工具箱的技能管理；旧的设置页链接会跳转过来。目录收录成功只表示安装包已保存，安装状态就绪后才能执行。添加来源包括：ZIP 上传，ClawHub 的 `@owner/slug` 或带版本形式，SkillHub 或自托管页面，GitHub/GitLab 仓库或目录 URL，skills.sh 链接，以及直接的 ZIP 或 `SKILL.md` URL。来源必须可匿名读取，下载不会附带用户的私有仓库凭据，私有技能应先导出 ZIP。`owner/slug` 有歧义，应改用 `@` 形式或完整 URL。技能包上限由 `MAX_SKILL_BUNDLE_SIZE_MB` 约束，文档写明默认 256 MiB，未设置时至少为普通文件上限，最高 512 MiB；从 GitHub 下载时按整个仓库压缩包计算。调整后要同时重启 app 与 frontend，使 Nginx 上限一致。

目录与安装是分开的：添加目录不执行安装；安装会在所选沙箱构建环境、安装依赖并校验可加载性，成功后发布新快照；重试复用已保存的包，可附带安装说明；升级是目录登记新版本后把新版本装到所选沙箱；停止安装把状态变为失败；停用保留记录但智能体不再选用；从沙箱卸载更新该沙箱镜像但保留目录包；删除目录条目要求已无沙箱安装引用，不会隐式卸载全部沙箱。同一技能可以装到多个沙箱，进度和失败原因分别记录。关闭进度界面不会停止安装。安装由内置技能安装智能体完成，缺少必需命令或未解决的外部前提时会判失败，不会因为没有依赖清单就标为就绪。升级或重试失败时，沙箱继续提供上一个就绪版本。每会话一台沙箱时，可用 `skill_rollout` 选择下一轮重建或仅新会话使用新镜像；共用沙箱模式不会自动重建已有机器。重建会丢失临时运行状态，需交付的文件应写入约定输出目录并由系统收集。对话里可以用 `@技能` 提示优先使用，但不会取消智能体对其它已授权技能的访问。未选沙箱、空间关闭脚本或后端能力不可用时，执行工具不会注册，提示词不能绕过。

沙箱后端中，Docker 需要镜像和可选的守护进程、TLS、资源限制、网络和空闲 TTL，一个会话一个长驻容器；CubeSandbox 与 E2B 需要控制面、模板和密钥，可自托管。`host` 只用于 Lite 桌面（当前文档范围为 macOS），未选命名沙箱配置时在本机项目目录执行，越界由操作系统拦截。曾经存在的 `local` 宿主机进程后端已移除，因为它在本机裸跑、没有隔离；Lite 的 `host` 不是它的替代项，也不出现在空间命名配置里。Docker 后端默认关闭，需系统管理员在网络安全设置中启用，或在尚未落库时用 `WEKNORA_SANDBOX_DOCKER_ENABLED=true` 回退；把 Docker socket 挂给 app 等于授予其控制宿主机 Docker 的能力。Docker 网络仅接受 `bridge` 或 `none`。远端 TCP 守护进程要配置 TLS 证书。自托管集群的数据面代理与“是否允许连接私网端点”是接入配置，与沙箱脚本能否出网不是同一项。脚本默认以沙箱内 root 执行，隔离来自容器或远端沙箱，`/workspace` 只是约定目录，并不限制 root 的文件访问。完整验证会真正创建沙箱、跑探针再清理。这些限制说明技能系统是高权限选配：默认核心问答不必打开 Docker，一旦打开就要按主机级风险来管理。

## 四十九、收束：如何把功能面当成可裁剪的企业套件使用

回到本文开头的判断：WeKnora 0.9.0 的功能非常多，而且大量是选配。核心始终是带角色的工作空间、文档知识库、docreader 解析、ParadeDB 上的向量与关键词索引、以及 Web 里带引用的问答。其余每一项都可以写成“为某类企业场景准备、但会引入新的依赖或重叠路径”。连接器之间的删除检测、限流和检查点不同；搜索引擎的密钥、过滤和是否允许自定义地址不同；飞书 Wiki 与云盘的权限和解析模式不同；技能目录与安装、Docker 默认关闭、已移除的裸机 local 后端，都在提醒“打开之前先看依赖和失败语义”。角色上 Owner 才管邀请，Viewer 可以提问，工具勾选不能单独关掉随沙箱注册的 Shell。评测没有界面，旧 MCP 进程已弃用，桌面尚未正式发布。把这些当作裁剪清单，而不是缺省全开的清单，才符合这套产品在源码里呈现的形状。

## 五十、自动化的计划选项、失败策略与容量上限

自动化在侧边栏有独立入口，可以由助手用一句话整理任务和计划，也可以在页面上手工填写名称、任务说明、一次性或周期执行、时区、会话方式、执行权限和通知。周期任务使用 Cron 表达式，最小间隔为 5 分钟。时区决定计划时刻，API 未指定时使用 UTC，文档建议明确填写 IANA 时区，例如 `Asia/Shanghai`。会话方式可以复用同一会话以积累上下文，或每次新建会话，并可选择携带上次成功结果。执行者固定为 WeKnora 助手，可单独指定模型，未指定时用助手自己的模型配置；若需要其它智能体，应在任务说明里描述分工，由助手协作，而不是在界面上另选一个任意自定义智能体作为调度主体。保存后应先手动运行一次再保持计划开启。取消一次运行不等于删除计划。暂停、恢复和查看运行记录、打开对应会话，都是日常操作。

运行选项包括：错过执行时可跳过或恢复后补跑一次，但不会把错过的全部时刻逐个补跑；上一轮未结束时选择跳过或排队；执行时长默认 30 分钟、最多 4 小时，等待审批的时间不计入；审批等待默认 24 小时，可设 5 分钟至 7 天；成功后可发站内通知。连续失败 3 次会自动暂停，需要查看原因后再恢复。服务中断后无法确定结果的任务可能进入“需要处理”，系统不会直接重放可能已经完成的写入。自动化以创建者当前权限执行，不保存一份永久用户凭证，角色变化会影响下次运行。任务仅由本人管理，当前自动化接口不对 API Key 开放。无人值守执行不能代替回答任意自由文本，任务说明应预先写清必要条件。长期授权可以覆盖已经出现过的审批需求，但仍受当前权限、范围、失效条件和强制审批约束。容量上，默认每个空间最多 100 个任务，每个进程同时执行 4 个任务，每个任务保留最近 200 条运行记录。调度依赖应用持续运行和数据库备份，个人电脑休眠或服务停止期间不能按时执行。这些上限和失败策略是功能的一部分：自动化适合周期检查和汇总，不适合当作保证恰好在某一秒执行的关键作业系统，也不应在未设审批的情况下自动执行破坏性写入。

## 五十一、长期记忆的模式、开关层次与管理员清理

长期记忆按工作空间和调用者身份隔离，IM 用户、嵌入访客与 Web 用户各自维护，不会自动跨空间合并。空间开关默认关闭，由 Admin 或 Owner 在设置中打开，并选择 `explicit_only`（只记录明确要求记住的内容，不跑后台蒸馏）或 `auto`（额外在后台抽取，按延迟和最短间隔合并）。默认写入模式是 `explicit_only`。个人可以关闭自己的记忆，即使空间已开启也不强制使用。智能体的 `memory_enabled=false` 可单独禁用，省略则继承空间设置。IM 和嵌入使用所绑定智能体的记忆偏好。个人记忆管理接口要求 API Key 为全权限，缩小能力的 Key 不能用来代管记忆。未确认的推断不会注入提示词；若推断是为了修改已有记忆，确认前旧条目继续生效，确认时一并替换；推断已失效时确认会失败，需要刷新列表。拒绝会留下抑制记录，减少重复提取。主题提升把反复讨论的主题变为长期关注。文档偏好记录反复引用的文档，移除偏好不会改变知识库权限。立即整理用于合并近义条目和归档到期事项。导出和清空只作用于自己的数据。

空间配置保存在租户的 `memory_config`，经专门接口读写。抽取延迟默认 90 秒（范围 5 到 3600），最短间隔默认 300 秒（最大 86400），用于合并短时间多轮并控制调用频率。提取说明最多 1000 字。每个身份的 active 和 pending 条数默认各 200、最大各 2000。主题形成关注的会话次数默认 3、最大 20。可以单独指定抽取模型和记忆召回用的向量模型；未配向量模型时只做词法匹配。向量召回和检索个性化在配置了向量模型时默认开启。记忆只影响问题理解和资料选择，不扩大知识库访问权。后台抽取对无法解析的模型输出最多重试三轮后跳过该段，跳过的消息不会自动补提取。无账号身份的管理目前提供管理员 API、不新增设置页，且 API Key 不可访问；清空会切换写入代次，阻止旧提取写回，但保留身份开关和聊天消息。关闭记忆后仍可用管理员接口清理存量。排查时应同时检查空间、个人和智能体三层开关，以及条目是否仍为 pending。

至此，功能文档对自动化容量与记忆默认关闭、分层开关和清理语义作了与官方说明一致的补充。它们都是选配，打开后会增加模型调用和管理责任，不改变默认的文档问答核心。

## 五十二、执行权限的三档与授权不能覆盖的边界

执行权限与空间角色、知识库授权同时生效：把智能体设为可以写入，并不使它获得调用者本来不能编辑的库或文件。三档为：`read_only` 只允许读取和探测，不能用一次审批绕过只读去写入；`confirm` 允许读取和探测，写入和破坏性操作都要先确认；`auto_write` 允许一般写入，但删除等破坏性操作以及被标记为始终审批的工具仍要逐次确认。助手会话中的选择不能超过空间设置的上限，WeKnora 助手默认上限是 `confirm`；普通智能体通过 `config.access_level` 配置，未配置上限时默认 `auto_write`。升级到 0.9.0 后应按实际场景核对这一默认值，以免普通智能体在未审查的情况下自动写入。审批卡片会说明操作、资源和影响，待审批状态可持久化，刷新页面后继续处理；恢复等待不等于自动重放一切，服务中断后无法确认的执行要先核对现状。可挂起的卡片在有到期时间时显示期限；不支持挂起的即时审批仍有倒计时，应在截止前处理。MCP 工具还叠加服务侧的风险与审批配置，强制逐次审批不会被普通授权跳过。会话里可以对符合条件的一般写入授予后续执行权限，范围限于该根会话，破坏性操作不能靠普通会话授权一概放行。自动化的长期授权可以基于实际审批记录选择操作和资源，甚至包括符合条件的破坏性操作，但需要逐次审批的操作不在此列，且不能覆盖角色检查，配置变化、过期、撤销或长期闲置都会使授权失效。涉及外部系统、技能安装或本机文件的任务，还要再受对应工具、沙箱和资源授权约束。不要把“自动执行”理解成无限权限。
